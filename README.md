# Violence Temporal Localization

영화 영상에서 **사람 대 사람 물리폭력이 일어나는 구간(start~end)** 을 찾아내는 파이프라인.
영상등급 심의를 보조하는 것이 과제 맥락이며, 프레임 한 장으로는 판단할 수 없는 항목을
시계열 문제로 다시 정의한 것이 이 프로젝트의 핵심입니다.

대학 데이터엔지니어링 수업의 팀 프로젝트(6명)이고, 이 저장소는 그중 **제가 담당한 범위**를 정리한 것입니다.
기여 범위는 아래 [기여 범위](#기여-범위)에 명시했습니다.

---

## 1. 이 프로젝트에서 가장 중요한 것

기술 스택보다 **두 번의 방향 전환**이 이 프로젝트의 내용입니다. 둘 다 "만든 것을 버린" 결정입니다.

### 전환 1. 객체 검출을 폐기하고 시계열 문제로 재정의

처음에는 담배·술잔·흉기 같은 **객체를 프레임 단위로 검출**하는 파이프라인을 만들었습니다.
데이터셋 2만여 장을 구축하고 Hugging Face에 호스팅까지 마쳤습니다.

그런데 이 접근은 **심의라는 문제를 풀지 못합니다.** 술잔이 화면에 있다는 사실은 등급과 거의 무관하고,
객체 검출은 좋은 사전학습 모델이면 대부분 잡히기 때문에 난이도도 낮습니다.
진짜 어려운 항목, 즉 **폭력과 공포는 프레임 한 장에 담기지 않습니다.** 시간축이 있어야만 정의됩니다.

그래서 객체 검출 트랙을 접고 **temporal localization**으로 갈아탔습니다.
폐기한 코드는 `docs/_archive_object_detection/`에 그대로 남겨뒀습니다.

### 전환 2. 자동 라벨링이 못 쓸 물건이라는 걸 실측으로 확인

Grounding DINO로 bbox를 자동 생성해 어노테이션 비용을 줄이려 했습니다.
샘플만 보면 그럴듯했지만, **전수 검수를 했더니 무너졌습니다.**

| 라벨군 | 검수량 | 결과 |
|---|---|---|
| explosion / car_accident / blood / abuse | 119 bbox 전수 | **False Positive 98.3%** (117 삭제 / 2 유지) |
| riot / weapon_knife / weapon_gun | 50 bbox 전수 | 유지 18 / 재라벨 3 / 삭제 29 |
| bottle / cup / cigarette | 373 중 층화 샘플 | 신뢰 가능 (clear keep 74%) |

실패 양상이 일관됩니다. `car_accident`는 멀쩡히 주차된 차, `explosion`은 네온사인과 채널 로고,
`blood`는 립스틱과 꽃다발을 잡았습니다. 즉 **행위·사건 라벨은 거의 노이즈이고, 사물 라벨만 쓸 만합니다.**

여기서 얻은 결론이 그다음 설계를 전부 결정했습니다. **폭력 라벨은 자동으로 만들 수 없으니 사람이 찍는다.**
그래서 어노테이션 도구를 직접 만들었습니다.

---

## 2. 어노테이션 도구를 직접 만든 이유

구간 라벨링을 하려고 기존 도구를 검토했는데 전부 막혔습니다.

- **CVAT**: `CVAT for video 1.1` export가 구간 태그를 지원하지 않습니다. box track으로 우회해야 해서 마찰이 큽니다.
- **VIA**: 단일 HTML로 무설치라 좋았지만 Oxford 서버가 hotlink를 403으로 막습니다.
- **Label Studio**: 타임라인은 네이티브로 되지만 팀원 전원이 설치해야 합니다.

그래서 Flask + OpenCV 단일 파일로 [`violence_annotator/`](violence_annotator/)를 만들었습니다.

- mp4를 넣으면 **2fps로 프레임을 추출**합니다. 37분 영화 4,470프레임 기준 **17.7초**
  (`grab()` + `retrieve()`로 전체 디코드 낭비를 제거한 결과입니다)
- 단축키 `1`로 violence 구간 시작·끝을 토글, `2`로 neg_hard(헷갈리는 격한 비폭력)를 찍습니다
- 저장하면 **빈 구간이 neg_easy로 자동 충전**되고 scene 번호가 붙습니다.
  라벨을 세 개 다 손으로 찍지 않아도 되게 한 것이 실제로 속도를 가장 많이 올렸습니다
- 타임라인 바에 구간이 색블록으로 표시되고, 블록 클릭으로 삭제, `Ctrl+Z` undo가 됩니다

출력은 `[movie_id, scene_num, start_frame, end_frame, label]` 한 줄 형식입니다.
제가 어노테이션한 영화 10편의 결과가 [`violence_annotator/output/`](violence_annotator/output/)에 들어 있습니다.

## 3. 최종 파이프라인

```
영상(mp4)
 → ① 2fps 프레임 추출 (cv2, 0-base)
 → ② ResNet50 (IMAGENET1K_V1, avgpool까지) → 프레임당 2048-d 벡터
 → ③ clip_len=4 / stride=2 슬라이딩 → (N, 4, 2048)
 → ④ 영상 단위 StandardScaler
 → ⑤ Transformer Encoder → 클립별 violence 확률
 → ⑥ Gaussian 스무딩 → 히스테리시스 병합 → 짧은 구간 제거
 → 폭력 구간 [start, end]
```

**모델**: `d_model=2048, nhead=8, num_layers=2, dim_feedforward=512`, 마지막 토큰을 `Linear(2048, 2)`로.
LSTM / TCN / BiLSTM / Transformer+Scheduler를 비교했고 **plain Transformer가 Test Acc 0.72로 가장 높아** 채택했습니다.

**후처리**가 체감 품질을 크게 바꿉니다. 클립 예측은 노이즈가 있어서 단일 threshold로 자르면
액션 중간의 짧은 dip에서 구간이 끊깁니다. 두 가지로 해결했습니다.

- **히스테리시스 병합**: 시작은 `t_high`(0.45)를 넘어야 하지만, 일단 켜지면 `t_low`(0.30) 밑으로
  떨어질 때까지 유지합니다. Canny edge detection과 음성 구간 검출에서 쓰는 이중 threshold와 같은 발상입니다.
- **Gaussian 가중 스무딩**(σ=1.0): 균등 이동평균을 대체했습니다. 가까운 강한 이웃일수록 크게 반영해서
  강한 액션이 옆의 dip을 끌어올립니다.

결과적으로 짧고 얕은 틈은 이어붙이고, 길거나 깊은 틈은 별개 구간으로 끊습니다.

## 4. 결과, 그리고 측정할 수 없다고 밝힌 것

**성능**: Test Accuracy 0.72, violence recall 약 0.6.
모델 구조를 바꿔도 비슷했기 때문에 병목은 모델이 아니라 **feature와 데이터**라고 판단했습니다.
과장하지 않고 그대로 적습니다.

### 영화 단위 폭력 비율은 이 파이프라인으로 측정할 수 없습니다

"폭력이 많은 영화나 적은 영화나 예측 폭력 비율이 비슷하게 나온다"는 관찰이 있었습니다.
모델 성능 문제로 보기 쉬운 현상이라 [`DE_PJ2/exp_norm_compare.py`](DE_PJ2/exp_norm_compare.py)로 검증했습니다.

| 정규화 | 예측 폭력비율 범위 | 표준편차 | GT 상관 |
|---|---|---|---|
| per-video (현재) | 31~37% | 1.9%p | 0.06 |
| global (학습 통계) | 14~51% | 11.6%p | -0.06 |

원인이 **두 개, 그것도 독립적으로** 있었습니다.

1. **per-video StandardScaler**가 영화 간 절대 강도를 지웁니다. 모든 영화가 35% 근처로 압축됩니다.
2. 더 근본적으로, **GT 폭력비율 자체가 전 영화 40.0%로 동일합니다(표준편차 0.0%p).**
   `build_clips.py`의 `neg_ratio=1.5`가 영화마다 1:1.5로 균형 샘플링해서 저장했기 때문입니다.
   즉 **데이터에 "이 영화가 얼마나 폭력적인가"라는 신호가 애초에 없습니다.**

global 정규화로 바꾸면 비율은 퍼지지만 GT 상관이 0이라 해결책이 아닙니다. 분포 불일치 노이즈일 뿐입니다.

**결론: 영화 단위 등급·강도는 이 파이프라인의 유효한 출력이 아닙니다.**
두 설계가 각각 cross-movie 강도를 제거하며, 둘 다 본래 목표인
temporal localization("이 영화의 어디가 폭력인가")에는 정확히 부합합니다.
등급 산출이 필요하면 균형 샘플링을 하지 않은 데이터로 재설계해야 합니다.

데모 UI의 "폭력 클립 비율" 지표에도 영상 간 비교 금지 경고를 달아뒀습니다.

## 5. 데모

[`DE_PJ2/demo_app.py`](DE_PJ2/demo_app.py) 단일 파일 Streamlit 앱입니다. CPU 추론으로 동작합니다.

- 임의 영상을 올리면 폭력 구간을 찾아 **진행바에 빨갛게 칠합니다**
- 빨간 구간 안을 클릭하면 그 구간의 첫 프레임으로 스냅해서 재생합니다
  (`st.video`는 진행바 스타일링이 불가능해서 HTML5 플레이어를 직접 만들었습니다)
- 확률 곡선 타임라인, 구간 표(구간·길이·최고확률), threshold 슬라이더

```bash
pip install -r requirements.txt
streamlit run DE_PJ2/demo_app.py
```

모델 가중치는 저장소에 없습니다. [Releases](../../releases)에서 `violence_transformer.pth`를 받아
`DE_PJ2/` 아래에 두면 됩니다.

> 데모 영상은 학습·테스트에 쓰인 71편 밖에서 고르는 것을 권장합니다.

```
├── DE_PJ2/                  학습 노트북, 데모 앱, 정규화 분석

├── labels/                  라벨과 검수 판정 기록 (json·txt, 약 13MB)

├── docs/
│   ├── README.md                       문서 인덱스

```

### 저장소에 없는 것과 그 이유

- **영화 프레임·클립 영상 약 22GB**: 저작권 문제로 공개하지 않습니다.
  설계 단계에서부터 "영화 원본은 보존하지 않는다"를 원칙으로 정했습니다.
- **팀원들이 어노테이션한 학습 피처**: 제 기여분이 아니라 제외했습니다.
- **모델 가중치·학습 피처·데모 패키지**: 파일 크기 때문에 [Releases](../../releases)로 분리했습니다.

## 7. 기여 범위

팀 6명이 카테고리를 나눠 진행한 프로젝트입니다. 이 저장소에 담긴 제 담당 범위는 다음과 같습니다.

- 폭력·흡연·음주 카테고리 데이터셋 구축과 Hugging Face 호스팅
- Grounding DINO 자동 라벨 전수 검수 및 폐기 판정, CVAT 정리 스크립트
- 구간 어노테이션 도구 설계·구현, 영화 10편 어노테이션
- 학습 데이터 클립 생성, 모델 비교 실험, Transformer 채택
- 정규화·샘플링 편향 분석 (4장)
- 데모 앱 구현

optical flow 피처는 팀원이 진행 중이었고, VideoMAE는 GPU 비용으로 보류했습니다. 둘 다 이 저장소 범위 밖입니다.

## 8. 한계

- Test Acc 0.72, violence recall 0.6이 천장입니다. ResNet 프레임 임베딩은 모션 정보를 담지 못합니다.
  optical flow나 video backbone(VideoMAE 등)이 다음 단계입니다.
- 골격 기반 접근(MediaPipe 2인 포즈 + 시계열 분류)도 설계하고 실험했지만 최종 채택하지 않았습니다.
  엉킨 몸싸움에서 키포인트가 무너지는 것이 예상된 리스크였고, 실험 노트북은 Release에 있습니다.
- 정적인 총 겨눔처럼 자세 변화가 작은 폭력은 신호가 약해 놓칩니다.
- 폭발·차량 사고는 스코프에서 제외했습니다. 사람 대 사람 물리폭력만 다룹니다.
- 어노테이션 교차 검수를 하지 못해 라벨 경계의 일관성이 검증되지 않았습니다.
